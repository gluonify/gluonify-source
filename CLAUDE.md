# CLAUDE.md: guidance for an AI assistant working on this project

This repository is the **starting point** for a Quarkus 4 service that runs on Gluonify. Read `README.md` first: it explains everything, step by step (also available as `README.fr.md`, `README.es.md`, `README.it.md`, `README.de.md`). This file summarizes what you must not break.

Shared context for every gluonify-* repository (rules, build order, pitfalls, conventions, Edge model): `/Users/a/dev/gluonify/CLAUDE.md`, loaded automatically with this file (written in French).

## Commands
- `mvn quarkus:dev`: development (hot reload, UI at http://localhost:8080, **no token needed**: the "dev" identity exists only in this profile).
- `mvn test`: 86 Java tests (REST, stores, webhooks, platform, documents, conformity). The UI is tested separately: `cd src/main/webui && npm test` (33 tests).
- The Gluonify SDK comes from the Maven repository of gluonify-sea (`gluonify.sea.maven.url` in `pom.xml`, default `https://images.gluonify.io/maven`); to build against another copy: `mvn verify -Dgluonify.sea.maven.url=file:///path/to/repository`.
- Native (what Gluonify runs): `docker build --target out --output type=local,dest=dist -f Dockerfile.build .` -> `dist/gluonify-source`.
- Rename the project: `python3 scripts/rename.py <groupId> <artifactId> [<package>]`, then `mvn test`.
- Java 25, Quarkus 4.0.0.Beta1, Jackson 3 (`tools.jackson.databind`, not `com.fasterxml`), GraalVM native (NIK 25).

## Platform rules (Gluonify's builder enforces them; `ConformityTest` checks them on your side)
- `quarkus-smallrye-health` is mandatory (R-SANTE). No plaintext secret in `application.properties`: use `${VARIABLE}` or `${app.key}` (R-SECRET). No `.env`, `*.pem`, `*.p12`, `*.jks` (R-FICHIER-SENSIBLE). No `quarkus-container-image-*` (R-IMAGE). `quarkus.http.host` never on loopback (R-ECOUTE). Native compilation never disabled (R-NATIF).
- **All configuration comes from the environment** (variables provided by the platform or its vault). Never hard-code a service address, a port or a password.

## Known pitfalls (do not fall into them again)
- **Native**: no `HttpClient` and no `SecureRandom`/`Random` in a `static` field (state frozen at build time): create it on first use. Read third-party JSON as a tree (`JsonNode`) rather than into undeclared classes. A type (de)serialized by Jackson outside a REST signature must carry `@RegisterForReflection`.
- **`/distributed/std`**: never rewrite a file or rename a directory that was just written; write NEW files under their final name. A directory listing can lag by ~3 s behind another replica.
- **Photon webhooks**: a 2XX status acknowledges, anything else causes a replay; be idempotent on `X-Gluonify-Event-Id`, across ALL replicas (`EventLedger`: never an in-memory map alone; files = `CREATE_NEW` of a new file, graph = uniqueness constraint).
- **Vault**: the `APP_` prefix exists only in the `<uuid>.app` space obtained with `"top": true` in the app spec; with a literal `topNamespace` keys arrive unprefixed.
- **Security**: `DevAuthentication` exists only in the `dev` profile (`@IfBuildProfile`). Do not extend it to production. Roles come from the Charm token (`source:read`, `source:write`).
- **Documents (Crystallon) are OPTIONAL**: without `source.crystallon.url` (`GLUONIFY_SERVICE_CRYSTALLON_URL`, provided when the spec says `"uses": ["crystallon"]`) there is no client, `POST /api/documents/invoice` answers 404 and nothing else changes: keep it that way (tests and the rest of the app must not need Crystallon). The files of `documents/generated/` are generated by Crystallon's "Code" tab: regenerate them, never edit them; every record of a generated payload goes into `DocumentsReflection` (native-only failure otherwise, guarded by `DocumentsReflectionTest`).
- **Which token Crystallon receives** = `source.crystallon.token` (`TokenMode`): `forwarding` (default; the bearer token of the caller, so it needs the audience `gluonify-crystallon` and the role `gluonify:crystallon:render`; nothing to forward outside a request) or `platform` (the application's own token: the file of `GLUONIFY_CRYSTALLON_TOKEN_FILE` = `source.crystallon.token-file`, which the platform provides for `"uses": ["crystallon"]` and the node agent renews; re-read at every call). `platform` without the variable stops the application at startup (`@Startup` producer); a Crystallon refusal is a 403 in `forwarding` and a 502 in `platform` (the caller cannot fix it). The SDK 0.6.0 has no `CrystallonTokens.platform()` (it is in the SDK sources only): `CrystallonClients.platform` does the same with `CrystallonTokens.file`; switch to the SDK method once a release has it. The setting is a MODE, never a token: error messages must not repeat its value.
- **R-SECRET and names**: a key containing `token`, `password`, `secret` or `key` must be written `${VARIABLE}` or `${VARIABLE:}` (empty default) in `application.properties`; the builder rejects `${VARIABLE:non-empty}` there, `ConformityTest` does not (it is more lenient). `source.crystallon.token=${SOURCE_CRYSTALLON_TOKEN:}` and its default (`forwarding`) lives in `TokenMode`.
- **`gluonify.json` = the services the builder deploys with**: Bup sends `uses` and `gdownDatabase` to `PUT /apps/<name>`, which REPLACES the whole spec. `gluonify.json` (root) must declare the same `uses` as `deploy/appspec.json` (`DeploySpecsTest` checks it); without it a build would remove `charm`, `gdown`, `crystallon` and the application token from the application.
- Code comments are in **English** in this repository; the README exists in five languages (English by default) and this file is English only. Keep commit messages plain.

## Where to change what
`NotesResource` = the model of a REST resource; `NoteStore` + `NoteStores` = where to plug in a store; `SourceConfig` + `application.properties` = configuration; `WebhookResource` = receiving Photon; `PlatformResource` = platform variables and calling another service; `documents/` = an optional integration with an SDK client (`DocumentsResource` + `CrystallonClients` + `TokenMode` + `InvoiceMapping`; `generated/` is Crystallon's output); `gluonify.json` = the services the builder declares at deployment; `src/main/webui` = the Vue UI (Quinoa).
